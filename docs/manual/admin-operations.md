## 1. 먼저 알아야 할 용어 다섯 개

이 문서 전체에서 계속 나오는 말입니다. 지금 다섯 줄만 읽어 두시면 나머지가 훨씬 쉽습니다.

| 용어 | 한 줄 설명 |
|---|---|
| **어드민(admin)** | 관리자 전용 웹 화면입니다. 이용자에게는 보이지 않고, 비밀번호를 알아야 들어갑니다. |
| **Firestore(파이어스토어)** | 구글이 제공하는 데이터 보관소입니다. 가입자 정보, 검사 결과, 그리고 앱이 실제로 읽는 시나리오 원고가 전부 여기 들어 있습니다. |
| **CSV** | 표를 쉼표로 구분해 저장한 텍스트 파일입니다. 엑셀·구글시트에서 표로 열립니다. 이 서비스의 문항과 시나리오 원고는 전부 CSV로 관리합니다. |
| **Mock 모드(목 모드)** | "연습 모드"입니다. 어드민이 Firestore에 연결되지 않았을 때 자동으로 들어가는 상태이며, **화면은 멀쩡히 뜨지만 진짜 데이터가 아니고 저장해도 실제로 반영되지 않습니다.** 이 문서에서 가장 조심해야 할 개념입니다. |
| **저장소(레포, repository)** | 프로그램 코드와 원본 CSV 파일이 보관된 곳입니다(GitHub). 앱이 직접 읽는 곳은 아니지만, 여기가 낡으면 나중에 복구할 때 옛날 내용이 되살아납니다. |

📌 **콘텐츠가 사는 곳은 세 군데입니다.** 이 셋의 관계를 모르면 4장·5장을 따라 하다 반드시
막힙니다.

```
① 구글시트 (콘텐츠 책임자 문서)   ← 사람이 원고를 쓰고 검수하는 곳 (원본)
        ↓  CSV로 내려받기
② 저장소의 CSV 파일 (GitHub)       ← 백업 겸 예비용. 앱은 평소엔 여기를 안 봅니다
        ↓  어드민에서 업로드
③ Firestore (DB)                   ← ★ 앱이 실제로 읽는 곳. 여기가 최우선입니다
```

**앱은 ③을 봅니다.** ③에 내용이 있으면 ②는 무시됩니다. 그래서 "파일만 고쳤는데 왜 앱이
그대로냐"는 일이 생깁니다. 반대로 ③만 고치고 ②를 안 고치면 GitHub 쪽이 조용히 옛날
내용으로 남아, 나중에 복구할 때 되살아납니다. **두 방향 모두 맞춰야 합니다.**

## 2. 접속하기 — 두 가지 방법과 그 차이

> 🔄 **2026-08-16 대변경: 웹 어드민이 Google Cloud Run으로 이사했고, 이제 웹도
> 실모드입니다.** 새 주소는 아래와 부록 A에 있습니다. 옛 Streamlit Community Cloud
> 배포본은 **같은 날 삭제 완료**됐습니다(로그인·실데이터 조회 확인 후).
> 이사한 이유: Community Cloud 약관(개인·비상업 전용, 개인정보 앱 제한)에 걸려
> 예고 없이 정지될 수 있었기 때문입니다.

어드민에 들어가는 길이 두 개 있고, **이제 둘 다 실제 데이터를 다룹니다.**

| | (A) 인터넷 주소로 접속 | (B) 맥에서 직접 실행 |
|---|---|---|
| 어디서 | **Google Cloud Run (웹)** — `<어드민 주소 — 팀 내부 공유>` | 개발용 맥북 |
| 실제 데이터 | **있음 (실모드, 2026-08-16부터)** | **있음 (실 데이터)** |
| 할 수 있는 일 | 실제 업로드·삭제·내보내기 전부 | 실제 업로드·삭제·내보내기 전부 + 터미널 스크립트 |

> ⚠️ 웹이 실모드가 되었으므로 **비밀번호가 유일한 잠금장치**입니다. 주소와 비밀번호를
> 팀 밖에 공유하지 마십시오. (옛 안내였던 "웹은 눌러도 안 바뀐다"는 2026-08-16부터
> 사실이 아닙니다.)

### 2-1. Mock 모드인지 실모드인지 구분하는 법 (가장 중요)

작업을 시작하기 전에 **매번** 확인하십시오. 네 가지 방법이 있고, 위에서부터 확실합니다.

**방법 0 — 왼쪽 사이드바의 배지를 본다 (가장 빠름, 항상 보임)**

왼쪽 메뉴 맨 위 `🦖 SYU-REACT 관리자` 제목 바로 아래에 색깔 있는 줄이 항상 떠 있습니다.

- 초록색 `🟢 실모드 — 저장하면 실제 서비스에 곧바로 반영됩니다.` → **진짜 데이터입니다.**
- 노란색 `🟡 Mock 모드 — 연습용. 저장해도 실제 DB에 남지 않습니다.` → **연습 모드입니다.**

이 배지는 어느 메뉴에 있든, 얼마나 스크롤했든 **항상 같은 자리에 보입니다.** 아래 방법
2·3의 메시지는 화면 위로 사라지지만 이것은 사라지지 않으므로, 평소에는 이것만 보셔도
됩니다. 다만 배지가 초록인데도 이상하다 싶으면 방법 1로 파일을 직접 확인하십시오.

**방법 1 — 파일이 있는지 본다 (맥에서 실행하는 경우, 가장 확실)**

`syu-react-admin` 폴더 안에 `.streamlit`이라는 폴더가 있고, 그 안에 `secrets.toml`이라는
파일이 있어야 합니다. 그리고 그 파일 안에 `[firebase]`라고 대괄호로 시작하는 줄이 있어야
합니다. 이 파일이 없거나 `[firebase]` 줄이 없으면 **무조건 Mock 모드**입니다.

- `.`으로 시작하는 폴더는 맥 파인더에서 기본으로 숨겨져 있습니다. 파인더에서
  `command + shift + .` (마침표)를 누르면 보입니다.

**방법 2 — 화면 맨 위 메시지를 본다**

로그인 직후 화면 위쪽에 다음 중 하나가 뜹니다.

- 초록색 `Firebase 연결 성공!` → **실모드입니다.** 진짜 데이터입니다.
- 노란색 `Firebase 인증 정보(secrets.toml)가 없습니다. Mock 모드로 실행합니다.` →
  **연습 모드입니다.**
- 빨간색 `Firebase 연결 실패 (에러: …)` → 키가 있으나 잘못됐습니다. 개발자에게 문의.

**방법 3 — 메뉴를 눌러 본다 (메시지가 스크롤 위로 사라졌을 때)**

왼쪽 메뉴에서 `문항 관리 (CSV)` 또는 `시나리오 관리 (CSV)`를 누릅니다. 화면 위쪽에
노란 상자로 이런 문구가 있으면 Mock 모드입니다.

> `Firebase 미연결(Mock 모드)입니다. 아래 편집·업로드·되돌리기는 **이 브라우저 세션에서만**
> 유지되고 실제 DB에는 반영되지 않습니다. 절차를 연습해 보는 용도로 쓰세요.`

또, `대시보드 홈`의 숫자가 전부 `0 명` / `0 건`이고 `유저 관리`에
`현재 가입된 유저가 없습니다.`가 뜬다면 Mock 모드일 가능성이 매우 큽니다. (실제로 가입자가
0명일 수도 있으므로 이것만으로 단정하지는 마십시오.)

🕳️ **함정 — "화면은 떠도 실데이터가 아닐 수 있습니다."**
Mock 모드에서도 업로드 버튼이 눌리고 `DB에 반영되었습니다`라는 초록 메시지까지 나옵니다.
다만 그 내용은 **브라우저 탭을 닫는 순간 사라집니다.** 원고를 올리고 "반영 완료"라고
보고했는데 앱은 그대로인 사고가 여기서 납니다. **업로드 전에 반드시 위 확인을 하십시오.**

### 2-2. (B) 맥에서 직접 실행하기 — 실제 작업용

터미널(응용 프로그램 → 유틸리티 → 터미널)을 열고 아래 두 줄을 **그대로** 붙여 넣습니다.
한 줄씩 입력하고 각각 엔터를 누르십시오.

```bash
cd ~/DEV_Mac/syu-react/syu-react-admin
venv/bin/streamlit run streamlit_app.py
```

- 첫 줄은 "그 폴더로 이동하라", 둘째 줄은 "어드민을 켜라"라는 뜻입니다.
- 잠시 뒤 브라우저가 자동으로 열립니다. 안 열리면 터미널에 표시되는
  `Local URL: http://localhost:8501` 주소를 복사해 브라우저 주소창에 붙여 넣으십시오.
- **터미널 창을 닫으면 어드민도 꺼집니다.** 작업하는 동안 열어 두십시오.
- 작업을 마치고 끄려면 터미널에서 `control + C`를 누릅니다.

> `venv/bin/`을 반드시 붙이십시오. 이것은 "이 프로젝트 전용으로 설치해 둔 파이썬"을
> 가리킵니다. 그냥 `streamlit run …`이라고 치면 맥에 기본 설치된 다른 파이썬이 잡혀
> 오류가 납니다. 자세한 것은 [13장](#13-절대-하지-말아야-할-것)을 보십시오.

### 2-3. 로그인

어드민을 켜면 자물쇠 아이콘과 함께 `🔒 관리자 로그인`이 뜹니다.
`어드민 비밀번호를 입력하세요` 칸에 비밀번호를 넣고 엔터를 누릅니다.

## 4. 시나리오·문항 CSV 교체하기

시나리오 원고나 검사 문항을 고쳤을 때 그것을 앱에 반영하는 절차입니다.
**이 서비스에서 가장 자주 하게 될 작업**입니다.

### 4-0. 전체 흐름 (먼저 이 다섯 단계를 외우십시오)

```
① 구글시트에서 원고 수정
       ↓
② 시트를 CSV 파일로 내려받기
       ↓
③ 어드민에 업로드 (← 여기서 앱에 반영됨)
       ↓
④ 앱에서 실제로 바뀌었는지 눈으로 확인
       ↓
⑤ 저장소(GitHub)에도 같은 파일 반영 요청  ← 빠뜨리기 쉬움. 꼭 하십시오
```

### 4-1. ① 구글시트에서 수정하고 ② CSV로 내려받기

콘텐츠의 원본(SSOT, Single Source of Truth = "진짜는 이것 하나")은 **콘텐츠 책임자의
구글시트**입니다. 항상 시트를 먼저 고치십시오.

구글시트에서 CSV로 내려받는 방법:

1. 내보낼 **탭(시트 하단의 이름표)**을 클릭해 선택합니다.
2. 상단 메뉴 `파일` → `다운로드` → `쉼표로 구분된 값(.csv)`을 클릭합니다.
3. 다운로드 폴더에 파일이 저장됩니다. 파일명은 신경 쓰지 않아도 됩니다.

> ⚠️ **엑셀로 열어서 다시 저장하지 마십시오.** 한국어 윈도우 엑셀은 CSV를 저장할 때
> 인코딩(글자를 저장하는 방식)을 바꿔 버려, 업로드했을 때 한글이 깨지거나 아예 읽히지
> 않습니다. 편집은 구글시트에서만 하고, 내려받은 파일은 열지 말고 그대로 올리십시오.

### 4-2. ③ 어드민에 업로드하기 — 시나리오

왼쪽 메뉴에서 `시나리오 관리 (CSV)`를 클릭합니다.

**1) 어느 CSV인지 고릅니다.** `관리할 CSV 종류`라는 가로 선택지가 있습니다.

| 선택지 | 무엇 | 최소 조건 |
|---|---|---|
| `비주얼 (배경/캐릭터)` | 씬마다 어떤 배경·캐릭터가 나오는지 | 메타 4열(NO, DOMAIN, REACTION_TYPE, TITLE) + 4씬 × (배경, 캐릭터1~3) = **최소 20열** |
| `대사` | 씬마다 나오는 대사 | NO, DOMAIN, REACTION_TYPE, SCENE_NUM, SCENE_TYPE, TEXT = **최소 6열** |
| `요정 조언·선택지` | 요정 3종의 조언과 선택지 → [5장](#5-요정-대사-올리기-scenariosangels) 참조 | NO, DOMAIN + 요정 3종 × (TITLE, DETAIL, AFTER) + HELPFUL_1~3 / UNHELPFUL_1~3 |
| `에필로그` | 영역마다 하나씩, 10편을 다 마치면 열리는 마무리 장면 → [6장](#6-에필로그-올리기-scenariosepilogue) 참조 | DOMAIN, SCENE_NUM, TITLE, BG, CHAR_1, CHAR_2, CHAR_3, KIND, TEXT (영역당 4~8씬 — 현재 25행) |

**2) 지금 DB에 무엇이 들어 있는지 확인합니다.** 고르자마자 상태가 표시됩니다.

- 초록색 `DB 반영됨 — scenarios/visual · 120행 / 20열 · 갱신 2026-08-05 14:32`
  → 이미 DB에 있고, 앱은 이것을 쓰고 있습니다.
- 노란색 `DB에 scenarios/angels 문서가 없습니다. 앱은 현재 프론트엔드에 내장된 로컬 CSV를
  사용 중입니다.` → 아직 DB에 없어 예비 파일을 쓰고 있는 상태입니다.

`현재 DB 내용 미리보기`를 펼치면 지금 들어 있는 내용의 앞부분 20행을 볼 수 있습니다.
`현재 DB CSV 내려받기` 버튼을 누르면 지금 DB 내용을 파일로 받을 수 있습니다.
**업로드하기 전에 이 버튼으로 현재 내용을 한 부 받아 두시길 권합니다** — 되돌리기 기능이
있지만, 파일을 손에 쥐고 있는 편이 마음이 편합니다.

**3) 새 파일을 올립니다.** 아래로 스크롤하면 `새 CSV 파일로 덮어쓰기`라는 제목이 있습니다.

- 파란 안내 상자에 "업로드 후 저장소(`src/assets/data/…`)에도 같은 파일을 반영하세요"라는
  문구가 있습니다. 이것이 위 ⑤단계입니다. 잊지 마십시오.
- `… CSV 업로드`라고 쓰인 회색 상자에 파일을 끌어다 놓거나, `Browse files`를 눌러 고릅니다.

**4) 검사 결과를 읽습니다.** 파일을 올리면 자동으로 검사가 돌고 미리보기가 나옵니다.

- 🔴 **빨간 상자(오류)**가 하나라도 있으면 **저장 버튼 자체가 나타나지 않습니다.**
  `치명적 오류를 수정한 뒤 다시 업로드하세요. 이 상태로는 저장할 수 없습니다.`라는
  안내가 대신 뜹니다. 시트로 돌아가 고친 뒤 다시 내려받아 올리십시오.
- 🟡 **노란 상자(경고)**는 저장을 막지 않습니다. 다만 "이대로 올리면 앱에서 이상하게
  보일 수 있다"는 뜻이므로 **반드시 읽고 판단**하십시오. 경고가 10건을 넘으면
  `… 외 경고 N건`으로 접혀서 표시됩니다.

자주 나오는 오류와 뜻:

| 메시지 | 뜻 | 조치 |
|---|---|---|
| `열이 N개뿐입니다. 최소 M개가 필요하며…` | 열(칸)이 모자랍니다 | 시트에서 열을 지우지 않았는지 확인 |
| `필수 열이 없습니다: NO, DOMAIN…` | 머리글 이름이 다릅니다 | 시트 첫 줄(머리글)을 원래대로 되돌립니다 |
| `NO 값에 언더스코어(_)가 있습니다` | 값에 `_`를 쓰면 안 됩니다 | 해당 칸의 `_`를 지웁니다 |
| `… 씬 번호가 [1, 2, 4] 입니다 (1~4 필요).` | 씬이 빠졌습니다 | 빠진 씬 행을 채웁니다 |

**5) 저장합니다.** 오류가 없으면 파란 `DB에 덮어쓰기` 버튼이 나타납니다. 누르면
`DB에 반영되었습니다. 앱을 새로고침하면 적용됩니다.`가 뜹니다.

[스크린샷: 시나리오 관리 화면 — 상태 배너·업로드 상자·검증 결과]

### 4-3. ③ 어드민에 업로드하기 — 검사 문항

왼쪽 메뉴에서 `문항 관리 (CSV)`를 클릭합니다. 방식은 시나리오와 거의 같습니다.

1. `검사 유형 선택`에서 `ADHD 검사` 또는 `스트레스 대처 기제 검사`를 고릅니다.
2. 화면 가운데에 **표 편집기**가 나옵니다. 칸을 직접 클릭해 고칠 수 있고, 행 추가·삭제도
   됩니다. 고쳤으면 `표 변경사항 DB에 저장`을 누릅니다 → `DB에 업데이트 되었습니다!`
   - **오탈자 한두 개 고치는 정도라면 이 방법이 가장 빠릅니다.** CSV를 오갈 필요가 없습니다.
   - 단 이 방법은 시트와 저장소에 자동 반영되지 않습니다. 고친 내용을 시트에도 반영하십시오.
3. 문항을 통째로 바꾸려면 아래 `새 CSV 파일로 덮어쓰기 (업로드)`에서 파일을 올리고
   `DB에 일괄 덮어쓰기`를 누릅니다.

문항 CSV의 열은 `id, part, question, type, options` 다섯 개이며, `type`은
`scale`·`yes-no`·`multiple-choice` 셋 중 하나여야 합니다. 다른 값을 넣으면 빨간 오류가 뜹니다.

권장 문항 수(어기면 노란 경고가 뜨지만 저장은 됩니다):
- ADHD: **6문항**
- 스트레스: **총 12문항**, `part`가 `인지`/`정서`/`행동` 각 4문항

> ⚠️ 스트레스 문항 수를 바꾸면 **점수 계산과 유형 판정이 함께 틀어집니다.** 문항 수 변경은
> 반드시 개발자와 상의하십시오. 문구만 다듬는 것은 안전합니다.

### 4-4. ④ 실제로 바뀌었는지 확인

1. 앱을 브라우저에서 열고 **새로고침**합니다(맥: `command + R`).
2. 고친 부분이 실제로 보이는지 확인합니다.
3. 안 바뀌었다면 [14장](#14-막혔을-때--증상별-대처)의 "고쳤는데 앱이 그대로입니다"를 보십시오.

### 4-5. ⑤ 저장소(GitHub)에도 반영 — 빠뜨리기 쉬움

어드민 업로드만 하면 **GitHub의 CSV 파일은 옛날 내용 그대로 남습니다.** 화면은 멀쩡해서
아무도 눈치채지 못하다가, 나중에 초기화하거나 앱을 다시 배포할 때 옛날 원고가 되살아납니다.

**개발자가 있을 때**: 아래 명령으로 어긋난 곳을 확인할 수 있습니다(읽기 전용이라 안전합니다).

```bash
cd ~/DEV_Mac/syu-react/syu-react-admin
venv/bin/python check_csv_sync.py
```

출력 예시와 뜻:

```
[scenarios]
  visual     ✅ 일치 (121행, a1b2c3d4, DB 갱신 2026-08-05 14:32)
  dialogue   ⚠️  불일치 — DB 갱신 2026-08-16 10:05
                 로컬  480행 11aa22bb
                 DB    492행 33cc44dd
  angels     DB 문서 없음 → 로컬 폴백 사용 중 (로컬 41행)
  epilogue   DB 문서 없음 → 로컬 폴백 사용 중 (로컬 22행)
```

- `✅ 일치` — 양쪽이 같습니다. 할 일 없음.
- `⚠️ 불일치` — 어긋났습니다. 보통 **DB가 최신**이므로, 어드민에서
  `현재 DB CSV 내려받기`로 받은 파일을 저장소에 반영해야 합니다.
- `DB 문서 없음` — 아직 DB에 안 올린 상태입니다. 어긋남이 아닙니다.

**개발자가 없을 때**: 위 명령을 직접 돌릴 수 없으므로, 다음처럼 남겨 두십시오.

1. 어드민에서 `현재 DB CSV 내려받기`를 눌러 파일을 받습니다.
2. GitHub 저장소의 **Issues(이슈)** 탭에서 `New issue`를 눌러 요청을 남깁니다.
   - 제목 예: `[CSV 동기화] scenario_angels.csv 저장소 반영 요청 (2026-09-05 업로드분)`
   - 본문에 무엇을 언제 올렸는지 적고, 내려받은 CSV 파일을 **드래그해 첨부**합니다.
3. 이렇게 해 두면 나중에 누가 보더라도 어느 쪽이 최신인지 알 수 있습니다.

### 4-6. 잘못 올렸을 때 — 되돌리기 (1단계)

`문항 관리 (CSV)`와 `시나리오 관리 (CSV)` 두 화면 모두, 맨 아래에
`이전 버전으로 되돌리기`라는 제목이 있습니다.

- 표에 **현재 버전**과 **이전 버전 (되돌릴 대상)**의 행 수·글자 수·크기·저장 시각이
  나란히 나옵니다. 먼저 이 숫자로 "정말 되돌릴 그 버전이 맞는지" 확인하십시오.
- `이전 버전 내려받기`를 누르면 되돌리지 않고 내용만 파일로 받아 볼 수 있습니다.
  확신이 없으면 이것부터 하십시오.
- `이전 버전으로 되돌리기`를 누르면 확인 창(`확인: 이전 버전으로 되돌리기`)이 뜹니다.
  `네, 되돌립니다`를 누르면 실행되고, `취소하기`로 빠져나올 수 있습니다.
- 되돌리면 `이전 버전으로 되돌렸습니다. 앱을 새로고침하면 적용됩니다.`가 뜹니다.

🔑 **되돌리기는 "맞바꾸기"입니다.** 되돌려도 지금 내용이 버려지지 않고 '이전 버전' 자리로
들어가므로, **한 번 더 누르면 원래대로 돌아옵니다.** 잘못 되돌려도 복구할 수 있습니다.

⚠️ **보관되는 이전 버전은 딱 한 개뿐입니다.** 두 단계 전으로는 못 갑니다.
`보관된 이전 버전이 없습니다.`라고만 적혀 있다면 아직 이 화면에서 한 번도 저장한 적이
없다는 뜻입니다. 한 번 저장하면 그때부터 되돌릴 수 있게 됩니다.
또한 **같은 내용을 두 번 올리면 보관본은 갱신되지 않습니다** — 실수로 같은 파일을 다시
올려도 되돌릴 지점이 사라지지 않도록 일부러 그렇게 만들어 두었습니다.

### 4-7. 배경과 대사가 맞는지 대조하기

`시나리오 관리 (CSV)` 화면 맨 아래 `조인 키 정합성 검사`가 있습니다.
`두 문서 대조하기` 버튼을 누르면 비주얼과 대사가 서로 짝이 맞는지 검사합니다.

- 초록 `정상 — 양쪽 모두 120개 키가 일치합니다.` → 문제 없음
- 빨강 `대사가 없는 비주얼 N건 (앱에서 빈 대사로 표시)` → 그 장면에서 **대사가 안 나옵니다.**
  반드시 고쳐야 합니다.
- 노랑 `비주얼이 없는 대사 N건 (앱에서 무시됨)` → 그 대사는 화면에 안 나옵니다.
  쓸모없는 행이므로 지우거나 비주얼을 추가하십시오.

> **요정 대사와 에필로그는 이 검사 대상이 아닙니다.** 짝을 맞추는 방식(조인 키)이 서로
> 다르기 때문이며, 화면에도 그렇게 적혀 있습니다. 두 CSV는 각각 올릴 때 전용 검사가
> 돌아갑니다([5-3](#5-3-올리기)·[6-4](#6-4-검사-결과-읽기)).

## 5. 요정 대사 올리기 (scenarios/angels)

**2026-08-18에 팀에서 요정 대사 원고를 받으면 실제로 밟게 될 절차입니다.**
4장의 일반 절차와 다른 점만 여기 모았습니다.

### 5-1. 원고가 어떤 형태로 오는가

- **정본은 영역별 CSV 파일 4개**입니다(`angels_이름.csv` 형식으로 노션 제출란에 올라옵니다).
  구글시트 `마. 요정 대사` 탭은 **팀원 검수용 사본**이며, 둘이 어긋나면 **CSV 파일이 우선**입니다.
- 분담: 영역별 담당자 4인(팀 내부 문서 참조)
- 4개 파일을 **하나로 합쳐야** 업로드할 수 있습니다. 어드민은 파일 하나만 받습니다.

### 5-2. 파일 합치기

구글시트에서 하는 것이 가장 안전합니다.

1. 새 구글시트를 만듭니다.
2. 첫 번째 CSV 파일을 `파일` → `가져오기` → `업로드`로 불러옵니다.
3. 나머지 3개도 같은 방법으로 불러오되, 가져오기 위치를 `현재 시트에 추가`로 지정합니다.
   **머리글(첫 줄)이 중간에 섞여 들어가면 지우십시오.** 머리글은 맨 위에 딱 한 줄만
   있어야 합니다.
4. 합쳐진 시트를 `파일` → `다운로드` → `쉼표로 구분된 값(.csv)`으로 내려받습니다.

**머리글은 정확히 이 17개, 이 순서여야 합니다:**

```
NO, DOMAIN,
ACCEPT_TITLE, ACCEPT_DETAIL, ACCEPT_AFTER,
REAPPRAISAL_TITLE, REAPPRAISAL_DETAIL, REAPPRAISAL_AFTER,
REFOCUS_TITLE, REFOCUS_DETAIL, REFOCUS_AFTER,
HELPFUL_1, HELPFUL_2, HELPFUL_3,
UNHELPFUL_1, UNHELPFUL_2, UNHELPFUL_3
```

| 열 | 뜻 |
|---|---|
| `DOMAIN` | 어느 에피소드인지 지정하는 **열쇠**입니다. `일상1`, `취업준비3`처럼 씁니다. |
| `NO` | 사람이 보기 편하라고 붙인 번호입니다. 프로그램은 이 값을 쓰지 않습니다. |
| `ACCEPT_*` / `REAPPRAISAL_*` / `REFOCUS_*` | 요정 3종(수용·재평가·재초점)의 원고입니다. |
| `*_TITLE` | 요정 카드에 보이는 한 줄 요약 |
| `*_DETAIL` | 요정을 눌렀을 때 나오는 조언 본문 |
| `*_AFTER` | 그 전략을 실행한 뒤 주인공(백설이)이 하는 1인칭 소감 |
| `HELPFUL_1~3` | "도움이 됐다"를 골랐을 때 나오는 이유 선택지 3개 → **[5-6](#5-6-도움비도움-요인-열-helpful_13--unhelpful_13)을 반드시 읽으십시오** |
| `UNHELPFUL_1~3` | "도움이 안 됐다"를 골랐을 때 나오는 이유 선택지 3개 → **[5-6](#5-6-도움비도움-요인-열-helpful_13--unhelpful_13)을 반드시 읽으십시오** |

⚠️ **영역명은 `취업준비`로 붙여 씁니다.** `취업 준비`처럼 띄우면 짝이 안 맞아 그 에피소드
원고가 통째로 반영되지 않습니다.

### 5-3. 올리기

1. `시나리오 관리 (CSV)` 메뉴로 들어갑니다.
2. `관리할 CSV 종류`에서 **`요정 조언·선택지`**를 고릅니다.
3. `요정 조언·선택지 CSV 업로드` 상자에 합친 파일을 올립니다.
4. 검사 결과를 읽습니다. 요정 CSV 전용 검사입니다:

| 메시지 | 색 | 뜻 · 조치 |
|---|---|---|
| `필수 열이 없습니다: DOMAIN — 에피소드 조인 키입니다.` | 🔴 | 머리글에 `DOMAIN`이 없습니다. 5-2의 머리글과 대조하십시오 |
| `DOMAIN이 빈 행이 N개 있습니다.` | 🔴 | 빈 줄이 섞였거나 영역명을 안 적었습니다 |
| `DOMAIN이 중복됩니다: 일상1, …` | 🔴 | 같은 에피소드가 두 번 있습니다. **뒤 행이 앞 행을 조용히 덮어씁니다.** 합칠 때 머리글이 중간에 섞였는지 확인 |
| `요정 원고 열이 없습니다: ACCEPT_AFTER, …` | 🟡 | 그 칸만 앱의 **기본 문구**로 나옵니다. 원고가 반영되지 않으니 열 이름을 고치십시오 |
| `선택지 열(HELPFUL_*/UNHELPFUL_*)이 하나도 없습니다.` | 🟡 | 전 회차가 기본 선택지를 씁니다 |

5. 오류가 없으면 `DB에 덮어쓰기`를 누릅니다.

### 5-4. 처음 올릴 때 주의 — 지금은 DB에 문서가 없습니다

**2026-08-26 기준으로도 `scenarios/angels` 문서는 아직 DB에 없습니다.** 그래서 이 화면에
들어가면 노란 경고와 함께 `로컬 CSV로 초기화 (Seed)` 버튼이 보입니다. 앱은 그동안
저장소에 들어 있는 기본 CSV를 쓰고 있으며, 화면상으로는 구분되지 않습니다.

- **이 버튼은 누르지 않아도 됩니다.** 새 원고를 바로 업로드하면 그대로 문서가 만들어집니다.
- 다만 **처음 업로드에는 되돌릴 이전 버전이 없습니다.** 되돌리기는 두 번째 업로드부터
  가능합니다. 그러니 **처음 올리기 전에는 특히 신중하게** 검사 결과를 읽으십시오.

### 5-5. 올린 뒤

1. 앱에서 요정을 눌러 원고가 실제로 바뀌었는지 확인합니다.
   (지금까지는 모든 에피소드가 같은 조언을 보여 줬습니다. 원고가 들어가면 **에피소드마다
   다른 조언**이 나와야 정상입니다.)
2. 저장소 반영 요청을 남깁니다([4-5](#4-5--저장소github에도-반영--빠뜨리기-쉬움) 참조).
   파일명은 `scenario_angels.csv`입니다.
3. 최종본을 구글시트 `마. 요정 대사` 탭에도 반영합니다
   ([13장](#13-절대-하지-말아야-할-것)의 서식 주의 참고).

### 5-6. 도움·비도움 요인 열 (`HELPFUL_1~3` / `UNHELPFUL_1~3`)

**2026-08-26부터 이 여섯 칸이 40편 전부에 채워졌습니다.** 이용자가 에피소드를 마치고
`도움이 되었어요` 또는 `잘 모르겠어요`를 고르면, 그 다음 화면에 "왜 그런가요"를 묻는
선택지 3개가 뜨는데 그것이 이 칸입니다.

🔑 **여기에는 다른 열과 완전히 다른 규칙이 하나 있습니다. 이것만은 지켜 주십시오.**

> **문구는 아래 팔레트 16개 중에서만 고릅니다. 편마다 새로 쓰지 마십시오.**

**왜 그런가 — 한 문단으로.**
앱의 회복 일기 보고서는 "가장 많이 고른 이유 3개"를 보여 줍니다. 그런데 그 집계는
**문구가 글자 그대로 같은지**로만 셉니다. 그래서 1편에 `자책이 줄어든다`, 2편에
`나를 덜 탓하게 됨`처럼 뜻이 같아도 글자가 다르면 **다른 이유 두 개로 세어집니다.**
편마다 고유한 문구를 쓰면 40편을 전부 플레이해도 모든 항목의 개수가 1이 되고,
보고서의 Top3는 "먼저 플레이한 순서"와 똑같아집니다. **오류 메시지가 뜨지 않고
조용히 무의미해지는** 종류의 사고라 더 위험합니다.

**규칙 세 줄:**

1. 문구는 아래 팔레트 **도움 8개 · 비도움 8개** 중에서만 씁니다. 띄어쓰기와 조사까지
   **글자 하나 다르지 않게** 복사해서 붙여 넣으십시오.
2. 한 편에는 도움 3개 · 비도움 3개를 고르며, **한 편 안에서 같은 문구를 두 번 쓰지
   않습니다.** 편마다 달라지는 것은 *문구*가 아니라 *고른 3개의 조합과 순서*입니다.
   (`_1`이 화면에서 맨 위에 나오므로 그 편에 가장 잘 맞는 것을 `_1`에 둡니다.)
3. **한 항목은 최소 4편 이상에 나와야 합니다.** 한두 편에만 넣으면 그 이유는 집계에서
   사실상 보이지 않습니다. (현재 배정은 도움 12~19편, 비도움 13~18편입니다.)

#### 팔레트 — 도움이 되었어요 (8개)

| 문구 | 어떤 경우에 고르는가 |
|---|---|
| `감정을 편안하게 해줌` | 불안·긴장·조바심 같은 들뜬 상태가 실제로 가라앉았다 |
| `지금 감정을 알아차림` | 내가 무엇을 느끼는지에 이름이 붙었다 (가라앉지 않아도 됨) |
| `나를 덜 탓하게 됨` | 자책·부끄러움이 줄고 "내가 문제"라는 결론에서 빠져나왔다 |
| `상황을 달리 보게 됨` | 사실과 내 해석이 분리되어 상황에 다른 설명이 붙었다 |
| `부담이 작게 느껴짐` | 상황이나 할 일의 덩치가 감당할 만한 크기로 줄었다 |
| `상대 입장이 이해됨` | 연인·동료·가족의 사정이나 의도가 달리 보였다 |
| `무엇부터 할지 분명해짐` | 첫 행동이 무엇인지 구체적으로 정해졌다 |
| `시작해 볼 마음이 생김` | 방법을 알았을 뿐 아니라 실제로 손을 댈 마음이 생겼다 |

#### 팔레트 — 잘 모르겠어요 (8개)

| 문구 | 어떤 경우에 고르는가 |
|---|---|
| `상황에 맞지 않음` | 조언이 전제한 조건이 내 처지에 없다 |
| `공감되지 않음` | 내 감정을 몰라주거나 건너뛴 느낌이다 |
| `마음이 편해지지 않음` | 말은 맞는데 감정은 그대로다 |
| `너무 이상적임` | 옳은 말이지만 그 순간의 나로서는 못 한다 |
| `이미 알던 이야기임` | 새로 얻은 것이 없다 |
| `어떻게 할지 막막함` | 하라는 건 알겠는데 첫 손이 잡히지 않는다 |
| `문제는 그대로 남음` | 마음과 별개로 상황·결과가 안 바뀐다 |
| `상대에겐 통하지 않음` | 내가 그렇게 해도 상대가 받아주지 않을 것 같다 |

> 비슷해 보여도 **일부러 나눠 둔 짝**이 있습니다. 고를 때 참고하십시오.
> · `감정을 편안하게 해줌`(가라앉았다) ↔ `지금 감정을 알아차림`(가라앉지는 않았지만 알게 됐다)
> · `무엇부터 할지 분명해짐`(방향) ↔ `시작해 볼 마음이 생김`(착수)
> · `너무 이상적임`(방법은 알지만 못 한다) ↔ `어떻게 할지 막막함`(방법 자체가 안 잡힌다)

#### 고치고 싶을 때

**어느 편의 3개를 다른 것으로 바꾸는 것**은 자유롭게 하셔도 됩니다. 위 규칙 2·3만
지키면 됩니다.

**팔레트의 문구 자체를 바꾸는 것**(예: `너무 이상적임` → `현실성이 없음`)은 다릅니다.

1. 그 문구가 들어간 **행을 전부 찾아 함께 바꿔야 합니다.** 한 편이라도 옛 문구가 남으면
   그때부터 그 둘은 서로 다른 항목으로 세어집니다.
2. 이미 쌓인 이용자 기록에는 **옛 문구가 그대로 남습니다.** 바꾸기 전과 후의 집계는
   합쳐지지 않으므로, 연구 데이터를 모으는 기간 중에는 문구를 바꾸지 마십시오.
3. 문구에 **`백설`이라는 이름을 넣지 마십시오.** 화면에서는 이용자가 지은 닉네임으로
   바뀌어 보이지만 저장되는 값은 원문이라, 화면과 집계가 어긋나 보입니다.
   길게 쓰는 것도 피하십시오 — 버튼 안에서 잘립니다.

> 이 팔레트를 어떻게 만들었는지, 어느 편에 무엇을 넣었는지는
> `docs/qa/2026-08-26-reason-palette.md`에 표로 남아 있습니다.

## 6. 에필로그 올리기 (scenarios/epilogue)

**2026-08-26에 새로 생긴 기능입니다.** 에필로그는 **영역마다 하나씩** 있는 마무리
장면입니다. 이용자가 그 영역의 10편을 모두 마치면 **11번째 카드**가 열리고(그전에는
목록 맨 아래에 자물쇠와 함께 `아직 잠겨 있어요`로 보입니다), 누르면 요정도 선택지도
없이 **몇 개 장면을 읽고 끝나는** 짧은 이야기가 나옵니다.

> **열리고 나면 그 카드는 목록 맨 위로 올라옵니다**(2026-08-26). 열 편을 다 지난
> 이용자에게 목록의 용건은 "다음 편 고르기"가 아니라 "아직 안 본 마무리 보기"인데,
> 열한 번째 줄에 있으면 매번 끝까지 내려야 닿기 때문입니다. **잠겨 있는 동안에는
> 지금까지처럼 맨 아래에 있습니다** — 아직 못 여는 카드가 첫 줄을 차지하면 지금 해야
> 할 1화가 밀려나서입니다. 운영자가 손댈 것은 없고, 문의가 오면 "다 깨면 맨 위로
> 올라온다"고 답하시면 됩니다.

4장의 일반 절차와 다른 점만 여기 모았습니다.

### 6-1. CSV의 생김새 — 다른 세 CSV와 축이 다릅니다

머리글은 정확히 이 9개, 이 순서입니다.

```
DOMAIN, SCENE_NUM, TITLE, BG, CHAR_1, CHAR_2, CHAR_3, KIND, TEXT
```

**한 줄이 한 장면(씬)입니다.** 씬 수는 **영역마다 4~8개**로 다를 수 있으므로 머리글을
뺀 줄 수는 **16~32줄** 사이입니다. **2026-08-26 현재 원고는 25줄**입니다
(직장 6 · 취업준비 6 · 연인 7 · 일상 6 — 각 영역의 마지막 한 줄이 아래 `KIND` 설명의
맺음말 씬입니다).

> 처음에는 네 영역 모두 4씬 고정이었습니다. 그런데 네 번째 씬에서 그대로 끝나
> "뚝 끊긴다"는 검수를 받아, 시간이 조금 흐른 뒤의 **매듭 장면**을 영역마다 필요한
> 만큼 덧붙였습니다. 그래서 지금은 영역마다 씬 수가 다릅니다.

| 열 | 뜻 | 주의 |
|---|---|---|
| `DOMAIN` | 어느 영역의 에필로그인지 | **`직장` · `취업준비` · `연인` · `일상` 네 가지뿐입니다.** 다른 CSV처럼 `직장1`이라고 회차 번호를 붙이지 마십시오 — 영역마다 한 편뿐이라 번호가 없습니다. **`취업준비`는 붙여 씁니다.** |
| `SCENE_NUM` | 장면 번호 | `1`부터 `8`까지 됩니다. 한 영역에 **1번부터 빠짐없이 한 번씩**, 최소 4개 최대 8개가 있어야 합니다. 중간을 건너뛰면(1·2·3·5) 그 영역이 통째로 사라집니다 |
| `TITLE` | 카드와 화면 위에 뜨는 제목 | 그 영역의 모든 줄에 **같은 제목**을 씁니다 (에피소드가 아니라 한 편의 제목이므로) |
| `BG` | 배경 그림 파일명 | 아래 6-2 목록에서 고릅니다 |
| `CHAR_1` `CHAR_2` `CHAR_3` | 화면에 세울 인물 (왼쪽·가운데·오른쪽) | 아래 6-2 목록에서 고릅니다. 비워 두면 그 자리에 아무도 서지 않습니다 |
| `KIND` | 장면인지 맺음말인지 | **비워 두면 장면입니다.** 맺음말 씬에만 `narration`이라고 적습니다 — 아래 설명 참조 |
| `TEXT` | 그 장면의 서술 | **3인칭 서술입니다.** 대사가 아니라 "백설은 …한다"처럼 밖에서 바라보며 씁니다. 쉼표가 들어가면 칸 전체를 큰따옴표로 감싸야 합니다 |

`TEXT`의 실제 예시(직장 1씬):

> 백설은 회의실 자리에 앉아 발표 자료를 펼친다. 지난번 숫자를 틀렸던 그 표가 화면에
> 다시 떠 있고, 옆자리 동료가 오늘도 잘 부탁한다며 노트북을 연다.

#### `KIND` — 맺음말 씬 (2026-08-26에 생긴 열)

앞의 장면들이 **극 안에서** 벌어지는 일을 보여 준다면, 각 영역의 **마지막 한 씬**은
극 밖으로 나와 다 본 이용자에게 직접 말을 겁니다 — 무엇이 달라졌는지 짚어 주고 응원
한 줄로 닫습니다. 앱은 이 씬만 **가운데 정렬·기울임꼴**로 그리고 위에 작게
`— 맺음말 —`을 붙여, 앞의 장면들과 눈에 띄게 갈라 보여 줍니다.

| `KIND`에 적는 값 | 어떻게 보이는가 |
|---|---|
| **빈 칸** | 보통 장면입니다. **원고 대부분이 여기 해당하므로 그냥 비워 두십시오** |
| `narration` | 맺음말 씬. 가운데·기울임꼴로 갈라져 보입니다 |

맺음말 씬을 쓰실 때 지킬 것은 셋입니다.

1. **영역마다 맨 마지막 한 줄에만** 붙입니다 (중간에 넣으면 이야기가 끊깁니다).
2. **인물 칸(`CHAR_1~3`)은 모두 비웁니다.** 극 밖의 목소리라 화면에는 배경만 남습니다.
   사람을 세워 두면 가운데 기울임꼴 글씨가 캐릭터 위에 얹혀 어색해집니다 (검사가
   🟡 경고로 잡아 줍니다).
3. **`BG`는 바로 앞 장면과 같은 배경**을 씁니다. 마지막에 화면이 튀지 않습니다.

문체는 앞 장면들과 다릅니다. 장면은 `백설은 …한다`(현재형 서술)로 쓰지만, 맺음말은
읽는 사람에게 건네는 말이라 `…하셨습니다` · `…해요`가 섞입니다. 실제 원고(직장):

> 지적을 받은 자리에서 곧바로 고치고 다음 안건으로 넘어가는 백설을 보셨습니다. 실수
> 자체보다 실수 뒤의 시간이 달라졌습니다. 회사에서 어떤 상황이 와도, 이제 백설은 그
> 시간을 스스로 다룰 줄 압니다. 앞으로도 같이 해봐요.

> 🔑 **`KIND` 열이 통째로 없는 옛 CSV를 올려도 오류가 나지 않습니다.** 그때는 모든
> 줄이 보통 장면으로 취급됩니다(= 열이 생기기 전과 똑같이 동작합니다). 다만 지금
> 원고에는 영역마다 맺음말이 하나씩 들어 있으므로, **`KIND` 열을 지운 채 덮어쓰면
> 맺음말이 평범한 장면처럼 보이게 됩니다.** 내려받아 고쳐 올리실 때 열을 지우지
> 마십시오.

**목록에 없는 이름을 쓰면 그림이 안 나옵니다.** 오타가 나도 오류 없이 빈 화면이 되므로
복사해서 붙여 넣으십시오.

**배경(`BG`) — 10종.** 저장소의 `syu-react-frontend/public/scenario/backgrounds/`에
들어 있는 파일들입니다.

> 바꿔 끼웁니다.** CSV에는 `lover_default.png`라고만 적으시면 됩니다.

1. `시나리오 관리 (CSV)` 메뉴로 들어갑니다.
2. `관리할 CSV 종류`에서 **`에필로그`**를 고릅니다.
3. 화면 위쪽에서 **지금 DB에 무엇이 들어 있는지** 확인합니다
   (초록 `DB 반영됨 — scenarios/epilogue …` 또는 노랑 `DB에 scenarios/epilogue 문서가
   없습니다. …`). 초록이면 `현재 DB CSV 내려받기`로 한 부 받아 두십시오.
4. `에필로그 CSV 업로드` 상자에 파일을 올립니다.
5. 검사 결과를 읽습니다(6-4).
6. 빨간 오류가 없으면 `DB에 덮어쓰기`를 누릅니다 →
   `DB에 반영되었습니다. 앱을 새로고침하면 적용됩니다.`
7. 저장소 반영 요청을 남깁니다([4-5](#4-5--저장소github에도-반영--빠뜨리기-쉬움) 참조).
   파일명은 `scenario_epilogue.csv`입니다.

### 6-4. 검사 결과 읽기

에필로그 전용 검사입니다. 다른 CSV와 메시지가 다릅니다.

| 메시지 | 색 | 뜻 · 조치 |
|---|---|---|
| `필수 열이 없습니다: DOMAIN, SCENE_NUM, TITLE, BG, TEXT …` | 🔴 | 머리글이 다릅니다. 6-1과 대조하십시오 (`KIND`는 없어도 오류가 아닙니다) |
| `DOMAIN이 빈 행이 N개 있습니다.` | 🔴 | 빈 줄이 섞였거나 영역명을 안 적었습니다 |
| `SCENE_NUM이 1~8가 아닌 값이 있습니다: …` | 🔴 | 그 줄은 앱에서 조용히 사라집니다. `1`~`8`으로 고치십시오 |
| `직장: 씬 번호가 [1, 2, 4] 입니다 (1번부터 빠짐없이 4~8개 필요) — 앱은 이 영역의 에필로그를 통째로 버립니다.` | 🔴 | 씬이 빠졌거나 번호가 겹칩니다. **한 씬이 모자라거나 번호가 건너뛰면 그 영역 전체가 안 나옵니다** |
| `알 수 없는 DOMAIN이 있습니다: 취업 준비 …` | 🟡 | 네 영역 이름과 다릅니다. **`취업 준비`처럼 띄어 쓴 경우가 여기 걸립니다** — 화면에 아예 안 뜨므로 사실상 고쳐야 합니다 |
| `에필로그가 없는 영역이 있습니다: 연인, 일상 …` | 🟡 | 아직 안 쓴 영역이 있다는 뜻입니다. 한 영역씩 채워 올리는 중이라면 정상입니다 |
| `총 행 수가 12개입니다 (16~32개 권장 — 4영역 × 4~8씬).` | 🟡 | 위와 같은 이유일 수 있습니다. 이 범위 밖이면 한 번 세어 보십시오 |
| `KIND에 모르는 값이 있습니다: 'narratoin' …` | 🟡 | 맺음말 씬의 철자가 틀렸습니다. **앱은 그 줄을 평범한 장면으로 그립니다** — `narration`으로 고치십시오 |
| `KIND가 narration인데 인물이 있는 행이 N개 있습니다 …` | 🟡 | 맺음말 씬에 사람이 서 있습니다. `CHAR_1~3`을 비우십시오 (6-1의 `KIND` 설명 참조) |
| `인물 열(CHAR_1~3)이 하나도 없습니다.` | 🟡 | 배경만 나오고 사람이 안 섭니다 |
| `TITLE이(가) 빈 칸이 N개 있습니다.` | 🟡 | 제목·배경·서술이 빈 칸이면 그 자리가 화면에서 비어 보입니다 |

### 6-5. 처음 올릴 때 주의 — 지금은 DB에 문서가 없습니다

**2026-08-26 기준 `scenarios/epilogue` 문서는 아직 DB에 없습니다.** 앱은 저장소에 들어
있는 **기본 CSV**(21행짜리 초안)를 쓰고 있으며, 이용자 화면에는 그 사실이 전혀
표시되지 않습니다. 즉 **에필로그는 이미 앱에서 열리고 있고, 팀이 확정한 정본 원고를
한 번 업로드하는 일이 남아 있는 상태**입니다.

- 노란 경고와 함께 `로컬 CSV로 초기화 (Seed)` 버튼이 보이지만, **누르지 않아도 됩니다.**
  정본을 바로 업로드하면 그때 문서가 만들어집니다.
- ⚠️ **처음 업로드에는 되돌릴 이전 버전이 없습니다.** 되돌리기는 두 번째 업로드부터
  됩니다. 그러니 **처음 올리기 전에 검사 결과를 특히 꼼꼼히 읽으십시오.**
- 두 번째부터는 다른 CSV와 똑같이 화면 맨 아래 `이전 버전으로 되돌리기`를 쓸 수
  있습니다([4-6](#4-6-잘못-올렸을-때--되돌리기-1단계)).

### 6-6. 올린 뒤 확인

에필로그는 **그 영역 10편을 모두 마친 계정에서만** 보입니다. 확인하시려면 4개 영역을
완주해 둔 검수용 계정으로 로그인해 시나리오 목록 맨 아래 카드를 눌러 보십시오.

- 잠겨 있으면 `아직 잠겨 있어요` / `10편을 모두 마치면 열려요`로 보입니다.
- 열려 있으면 CSV의 `TITLE`이 카드에 그대로 뜨고, 한 번 본 뒤에는 `봤어요` 표시가
  붙습니다. 누가 언제 봤는지는 [11-3](#11-3-시나리오-진행-탭)에서 확인합니다.

## 7. 연구용 데이터 내보내기

효과 검증 결과보고서를 쓸 때 쓰는 기능입니다. 이용자별로 검사 결과와 시나리오 진행 요약을
한 행씩 편 CSV를 내려받습니다.

`검사 결과 분석` 메뉴로 들어가 **아래로 스크롤**하면 `연구용 데이터 내보내기`가 있습니다.
(위쪽 그래프 두 개 아래에 있습니다.)

### 7-1. 절차

1. `개인정보 마스킹 (권장)` 체크박스를 확인합니다. **기본은 켜짐(✓)입니다.**
2. `내보낼 데이터 준비하기` 버튼을 누릅니다.
3. `N명 / M개 열`이라는 안내와 함께 앞 20행 미리보기가 나옵니다.
4. 파란 `CSV 내려받기` 버튼을 누르면 파일이 저장됩니다.
   - 파일명: `syu-react-research-20260916-1430.csv` (뒤는 내려받은 날짜·시각, 한국 시간)
   - 마스킹을 끄면 파일명에 `-unmasked`가 붙습니다.

### 7-2. "마스킹"이 무슨 뜻인가 — 무엇이 가려지는가

**마스킹(masking)이란 개인을 특정할 수 있는 정보를 가리는 것**입니다.

**마스킹 켜짐(기본)일 때 — 아래 다섯 항목은 파일에 열 자체가 만들어지지 않습니다:**

- `uid` (계정 고유번호 원문)
- `email` (이메일 주소)
- `display_name` (이름)
- `photo_url` (프로필 사진 주소)
- `character_nickname` (캐릭터 닉네임)

대신 `uid_hash`라는 열이 들어갑니다. 이것은 계정 번호를 되돌릴 수 없게 변환한 10자리
문자열입니다.

🔑 **핵심**: **같은 사람은 항상 같은 `uid_hash`가 됩니다.** 그래서 사전·사후 검사를
같은 사람끼리 짝지어 비교하는 분석은 **마스킹을 켠 채로도 그대로 됩니다.**
연구 분석의 대부분은 마스킹 ON으로 충분합니다.

성별(`character_gender`)은 가리지 않습니다. 그것만으로는 개인을 지목할 수 없고, 하위집단
분석에 필요하기 때문입니다.

### 7-3. 마스킹을 꺼야 하는 경우와 그때의 주의

체크박스를 해제하면 화면에 **빨간 경고**가 뜹니다:

> `마스킹 OFF — 연구 목적 외 반출 금지.` 이메일·이름·닉네임과 uid 원문이 그대로 나갑니다.
> 내려받은 파일은 공용 드라이브나 메신저에 올리지 마시고, 분석이 끝나면 삭제하세요.

**꺼야 하는 경우는 사실상 두 가지뿐입니다:**

1. **특정 이용자의 개인정보 열람 요청에 응답할 때** — 그 사람의 행을 찾으려면 이메일이
   필요합니다([9장](#9-문의와-개인정보-요청-대응) 참조).
2. **오프라인 실험 참가자 명단과 대조해야 할 때** — 누가 참여했는지 확인이 필요한 경우.

**끌 때 지켜야 할 것:**

- 내려받은 파일을 **구글 드라이브 공용 폴더, 카카오톡, 노션에 올리지 마십시오.**
- 개인 컴퓨터에 두고, 필요한 작업이 끝나면 **삭제하고 휴지통도 비우십시오.**
- 논문·보고서에 붙일 표에는 절대 이메일 열을 남기지 마십시오.
- 이 설정은 브라우저를 닫으면 **자동으로 마스킹 켜짐 상태로 돌아갑니다.**

### 7-4. 숫자를 읽을 때 주의할 두 가지

파일을 내려받는 화면 아래에 이런 안내가 있습니다. 뜻을 풀면 이렇습니다.

- **`adhd_score_band`는 임상 진단 기준이 아닙니다.** 그냥 점수를 20점 단위로 나눈
  표시용 구간입니다. 보고서에서 "이 구간 이상은 ADHD"처럼 인용하면 **안 됩니다.**
- **`helpful_rate`가 빈 칸인 것과 `0`인 것은 다릅니다.** 빈 칸은 "시나리오를 한 번도 끝까지
  안 했다"는 뜻이고, `0`은 "끝냈지만 한 번도 도움이 안 됐다고 답했다"는 뜻입니다.
  분석할 때 빈 칸을 0으로 채우면 결과가 왜곡됩니다.

### 8-2. 한 사람을 골라 조치하기

표 아래 `유저 계정 제어 (Auth & DB)`에서 `관리할 유저 선택 (이메일)` 목록을 열어
대상자의 이메일을 고릅니다. 고르면 `선택된 유저 UID: … / 현재 상태: 활성`처럼 표시됩니다.

**여기서 고른 사람에게만 아래 버튼이 적용됩니다. 이름을 두 번 확인하십시오.**

버튼은 가로로 세 개입니다.

**① `계정 정지 (Disable)` / `계정 활성화 (Enable)`**

상태에 따라 둘 중 하나만 보입니다.

- `계정 정지 (Disable)`을 누르면 `경고: 계정 정지` 창이 뜹니다.
  `네, 정지합니다`를 누르면 그 사람은 **로그인할 수 없게 됩니다.**
  데이터는 지워지지 않습니다.
- 정지된 사람이 앱에서 로그인을 시도하면
  `정지된 계정입니다. 관리자에게 문의하세요.`라는 안내를 받습니다.
- 되돌리려면 같은 자리의 `계정 활성화 (Enable)`을 누릅니다. **확인 창 없이 즉시**
  활성화되며 `… 계정이 다시 활성화되었습니다.`가 뜹니다.

> 부적절한 이용이 의심될 때는 **삭제가 아니라 정지**를 먼저 쓰십시오. 되돌릴 수 있습니다.

**② `비밀번호 재설정 링크 만들기`**

이름 그대로 **링크를 만들어 줄 뿐, 메일은 나가지 않습니다.** 누르면 이렇게 표시됩니다.

```
재설정 링크를 만들었습니다. 메일은 나가지 않았습니다 —
아래 주소를 복사해 본인에게 직접 보내 주세요.

https://…
```

링크 상자 오른쪽 끝에 복사 아이콘이 있습니다. **이 링크를 복사해 문의하신 분께 직접
메일로 보내 드려야 합니다.**

⚠️ 이 링크를 가진 사람은 그 계정의 비밀번호를 바꿀 수 있습니다. 단체 채팅방이나 공개된
곳에 붙여 넣지 마십시오. **본인 확인이 된 뒤, 본인 메일 주소로만** 보내십시오.

**③ `계정 영구 삭제 (Delete)`** — 🔴 **되돌릴 수 없습니다**

누르면 `경고: 계정 영구 삭제` 창이 뜨고 이렇게 적혀 있습니다.

> 정말로 '…' 유저를 삭제하시겠습니까? 이 작업은 절대 되돌릴 수 없으며, 기존의 모든 검사

여러 항목을 표로 정리해 드려야 하거나 여러 사람을 한꺼번에 다뤄야 할 때는 아래처럼
내보내기를 쓰셔도 됩니다.

1. `검사 결과 분석` → `연구용 데이터 내보내기`
2. `개인정보 마스킹` 체크를 **해제**합니다(빨간 경고가 뜹니다)
3. `내보낼 데이터 준비하기` → `CSV 내려받기`
4. 엑셀에서 열어 **요청자의 이메일이 있는 행 하나만** 남기고 나머지는 지웁니다
5. 그 한 행을 회신에 담아 보냅니다
6. **내려받은 원본 파일은 즉시 삭제합니다** (다른 사람들의 이메일이 전부 들어 있습니다)

이 방법으로 제공되는 것: 가입일, 검사 완료 시각, ADHD 점수, 스트레스 유형과 영역별 응답
수, 시나리오 완주 수, 전략 선택 횟수, 마지막 플레이 시각.

이 **내보내기 방법으로는 제공되지 않는 것**: 문항별 원응답(어느 문항에 무엇을
골랐는지), 에피소드별 상세 진행도, 회복 일기 내용.

→ 앞의 세 가지 중 **문항별 원응답과 에피소드별 진행도는 [11장](#11-유저-상세-조회정정)의
유저 상세 화면에 나옵니다.** 회복 일기 내용만은 어느 화면에도 없으므로, 그것까지
요구하시면 **개발자에게 요청**해야 합니다.

**③ 정정 요구 — 진행 기록은 가능, 계정 정보는 개발자 요청**

- 대부분은 본인이 앱에서 해결할 수 있습니다. 캐릭터 닉네임 변경, 검사 다시 하기,
  데이터 초기화는 마이페이지에서 됩니다. **먼저 이쪽을 안내**하십시오.
- **잘못 남은 진행 기록·검사 결과를 지우는 것**은 [11-4](#11-4-진행도-정정-탭-되돌릴-수-없습니다)의
  `진행도 정정` 탭에서 하실 수 있습니다 (되돌릴 수 없으니 표를 먼저 읽으십시오).
- 앱에서도 어드민에서도 안 되는 정정(예: 가입 이메일 변경)은 **개발자 요청**이
  필요합니다. 요청 내용과 접수일을 기록해 두고, 이용자에게는 처리에 시간이 걸린다는
  점을 안내하십시오.

### 9-3. 자주 오는 다른 문의

| 문의 내용 | 대응 |
|---|---|
| 로그인이 안 됩니다 | 어드민에서 `상태`를 확인합니다. `정지됨`이면 정지 사유를 확인하고, 문제없으면 `계정 활성화 (Enable)`. 비밀번호를 잊으신 경우는 [8-2 ②](#8-2-한-사람을-골라-조치하기)의 재설정 링크를 전달 |
| 검사를 다시 하고 싶습니다 | 앱 마이페이지에서 본인이 직접 초기화할 수 있습니다. 어드민에는 개별 초기화 기능이 없습니다 |
| 시나리오 진행이 이상합니다 | 어드민으로는 손댈 수 없습니다. 증상·계정·기기를 받아 개발자에게 전달하십시오 |
| 내용이 바뀌었는데 앱은 그대로입니다 | [14장](#14-막혔을-때--증상별-대처) 참조 — 대부분 DB에 안 올린 경우입니다 |

## 10. 약관·공지 관리

`약관·공지 관리` 메뉴입니다. 약관·처리방침 전문, 보호책임자 이름과 연락처, 공지 배너를
**개발자 없이** 고칠 수 있게 만든 화면입니다.

화면 위쪽에 가로 탭 여섯 개가 있습니다.

| 탭 | 하는 일 |
|---|---|
| `운영 정보` | 개인정보 보호책임자 성명, 보호책임자 연락처(처리방침 제10조), 1:1 문의 주소, 법무 문서 버전 |
| `이용약관 전문` | 이용약관 조항 편집 |
| `개인정보 처리방침 전문` | 처리방침 조항 편집 |
| `마케팅 수신 동의` | 동의 항목 표시 여부 · 동의 전문 · **동의자 이메일 추출** → [10-1](#10-1-마케팅-동의자-이메일-추출하기-bcc-붙여넣기용) |
| `공지 배너` | 앱에 띄우는 공지 문구 |
| `저장 이력` | 위 항목들을 저장·되돌린 기록 |

여기 저장한 값이 **없으면** 앱은 코드에 들어 있는 기본값으로 조용히 되돌아갑니다.
[4장](#4-시나리오문항-csv-교체하기)의 CSV와 같은 규칙이며, 화면에 아무 표시도 남지
않으므로 저장한 뒤에는 탭 안의 `코드 기본값 대비 현재 상태`를 확인하십시오.

> 조항 편집 자체의 상세 절차는 아직 이 문서에 없습니다. 지금 실제로 쓰게 될 기능은
> 아래 10-1이므로 그것부터 적었습니다.

### 10-1. 마케팅 동의자 이메일 추출하기 (BCC 붙여넣기용)

**2026-08-18에 생긴 기능입니다.** 이벤트나 새 영역 공개 소식을 **광고성 메일**로 보낼 때,
"보내도 되는 사람"의 주소만 모아 주는 기능입니다.

🔑 **어드민은 메일을 보내지 않습니다. 주소를 모아 줄 뿐입니다.** 실제 발송은 여러분이
쓰시는 메일 프로그램(Gmail 등)에서 하십시오. 어드민에 발송 버튼을 일부러 두지
않았습니다 — 잘못 눌러 나간 메일은 되돌릴 수 없기 때문입니다.

**절차**

1. `약관·공지 관리` → `마케팅 수신 동의` 탭으로 들어갑니다.
2. 아래로 스크롤해 `동의자 이메일 일괄 추출 (BCC 붙여넣기용)`을 찾습니다.
3. 빨간 경고와 노란 경고를 읽습니다(아래 10-2).
4. `동의자 이메일 추출하기` 버튼을 누릅니다.
5. 요약 문장이 나옵니다. 예:
   > **수신자 3명** — 현재 수신 동의 상태인 4명 중 이메일 없음 1명, 주소 중복 0명을 뺀
   > 수입니다 (전체 12명).
   >
   > 가입 시 동의했다가 마이페이지에서 수신을 거부한 **1명은 이미 제외**했습니다.
6. 그 아래 회색 상자에 주소가 `a@example.com, b@example.com` 형태로 **한 줄**로 나옵니다.
   상자 오른쪽 끝의 복사 아이콘을 눌러 복사합니다.
7. 표와 함께 `CSV 내려받기` 버튼이 있습니다. 기록으로 남기시려면 받으십시오
   (파일명 예: `syu-react-marketing-recipients-20260826-1430.csv`, 열은
   `email` · `marketing_agreed_at` · `uid` 세 개입니다).

**요약 숫자의 뜻**

| 말 | 뜻 |
|---|---|
| `전체 N명` | 가입자 전체 |
| `현재 수신 동의 상태인 N명` | 지금 이 순간 보내도 되는 사람 (거부한 사람은 이미 빠져 있음) |
| `이메일 없음` | 동의는 했는데 계정에 주소가 없어 보낼 수 없는 사람 |
| `주소 중복` | 같은 주소로 계정을 두 개 만든 경우. 한 번만 보냅니다 |
| `수신자 N명` | **실제로 뽑힌 주소 개수.** 여기 숫자가 곧 받는 사람 수입니다 |
| `… 수신을 거부한 N명은 이미 제외했습니다` | 아래 10-3 참고 |

### 10-2. 보내기 전에 — 반드시 지킬 것 세 가지

**① 반드시 숨은참조(BCC)에 붙여 넣으십시오.** 화면에도 빨간 상자로 적혀 있습니다.
받는사람(To)이나 참조(CC)에 넣으면 **동의자 전원의 이메일 주소가 서로에게 그대로
보입니다.** 한 번 나간 메일은 회수할 수 없고, 이것은 개인정보 유출 사고로 신고
대상이 됩니다.

**② 목록을 다른 일에 쓰지 마십시오.** 이 주소는 "광고성 정보를 받겠다"고 동의한
범위에서만 쓸 수 있습니다. 공용 드라이브·메신저·협력사에 공유하지 마시고, 발송이
끝나면 내려받은 파일을 삭제하십시오.

**③ 메일 자체가 지켜야 할 형식이 있습니다.** 정보통신망법 제50조에 따라 **제목 맨 앞에
`(광고)`를 붙이고, 본문에 무료로 수신을 거부하는 방법을 적어야** 합니다. 또 **밤 9시부터
다음 날 아침 8시 사이에는 보내지 않습니다**(마케팅 동의 전문 제8조에 그렇게 게시해
두었습니다).

🔴 **그리고 발송 전에 반드시 처리해야 할 법무 3종이 있습니다. 아직 처리되지
않았습니다(2026-08-26 기준).**

| 무엇 | 왜 |
|---|---|
| **동의 문안 검토** | 지금 들어 있는 마케팅 동의 전문은 **법무 검토를 받지 않은 임의 초안**입니다(2026-08-18 작성). 어드민 화면에도 그렇게 경고가 붙어 있습니다 |
| **"광고 없음" 문구와의 충돌 정비** | 🔴 **이것이 가장 중요합니다.** 지금 게시 중인 **이용약관 제4조 4항**은 *"본 서비스는 무료로 제공되며, 서비스 내 결제 기능이나 광고가 포함되어 있지 않습니다"*라고 적고 있고, **개인정보 처리방침 제2조**는 *"수집된 개인정보는 광고성 정보 전송에 활용하지 않습니다"*라고 적고 있습니다. **이 두 문장을 그대로 둔 채 광고 메일을 보내면 게시한 약관을 스스로 어기는 것이 됩니다.** 보내기로 결정하셨다면 두 조항을 먼저 고치십시오 |
| **법무 문서 버전(`LEGAL_VERSION`) 인상 여부** | 약관·처리방침 내용을 고쳤다면 `운영 정보` 탭의 `법무 문서 버전`도 올려야 합니다(현재 `2026-08-16`). 이 값은 이용자의 동의 기록에 함께 저장되므로, 안 올리면 "어떤 내용에 동의한 것인지"를 나중에 구분할 수 없습니다 |

> **광고 메일을 보낼 계획이 없다면 위 세 가지는 하지 않아도 됩니다.** 지금 상태(광고를
> 보내지 않음)가 게시된 약관과 일치하기 때문입니다.

### 10-3. 수신거부(수신 동의 철회)는 어떻게 처리되나

**따로 하실 일이 없습니다. 자동으로 빠집니다.**

- 이용자는 앱 `마이페이지` → `알림 설정` → `마케팅 정보 수신` 스위치를 꺼서 직접
  거부합니다. 끄면 화면에 `마케팅 정보 수신을 해지하였습니다.`가 뜹니다.
- 그렇게 거부한 사람은 **다음에 추출할 때 목록에서 자동으로 빠집니다.** 요약 문장의
  `… 수신을 거부한 N명은 이미 제외했습니다`가 그 숫자입니다.
- 가입할 때 거부했다가 나중에 켠 사람은 **반대로 목록에 들어옵니다.**

⚠️ **다만 목록은 "뽑은 그 순간의 사진"입니다.** 화면에도
`2026-08-26 14:30 (KST) 기준 스냅샷입니다.`라고 시각이 찍혀 나옵니다.
어제 뽑아 둔 줄을 오늘 붙여 넣으면 **그 사이에 거부한 사람에게도 메일이 나갑니다.**
**발송 직전에 다시 추출해서 쓰십시오.** 예전 목록을 재사용하지 마십시오.

메일로 수신거부를 요청하신 분이 있다면, 본인이 앱에서 직접 끄실 수 있다고 안내하시는
것이 가장 빠릅니다(마이페이지 → 알림 설정). 어드민에는 대신 꺼 드리는 버튼이 없으므로,
직접 하기 어려운 분이면 개발자에게 요청하십시오.

## 11. 유저 상세 조회·정정

한 사람이 **어디까지 진행했는지** 확인하고, 잘못 남은 기록만 골라 지우는 화면입니다.
문의가 들어왔을 때 쓰는 창구입니다.

**위치**: `유저 관리` 메뉴 안에서 **아래로 스크롤**하면 `유저 상세 조회 · 진행도 정정`이
있습니다. 별도 메뉴가 아닙니다.

`상세를 조회할 유저 (이메일)`에서 대상자를 고르면 `대상 — (UID) / (이메일)`이 표시되고,
그 아래에 탭 네 개가 나옵니다.

| 탭 | 무엇이 보이나 |
|---|---|
| `프로필 · 동의` | 가입일·닉네임·성별 등 프로필과 **약관 동의 기록**(`termsConsent`) |
| `검사 결과` | ADHD·스트레스 검사 요약과 **문항별 원응답**(펼침 상자 `문항별 응답 (Raw)`) |
| `시나리오 진행` | 영역별 진행 상황, 완료 보고서·**에필로그 열람 기록**, 에피소드별 기록 |
| `진행도 정정` | 기록을 골라 삭제 (되돌릴 수 없음) |

### 11-1. `프로필 · 동의` 탭

`동의 기록 (termsConsent)`은 **가입할 때 무엇에 동의했는지의 증빙**입니다.
`동의 기록이 없습니다. 약관 동의 화면이 생기기 전에 가입한 계정일 수 있습니다.`라고
나오면 오류가 아니라 옛 계정이라는 뜻입니다.

### 11-2. `검사 결과` 탭

여기서 **문항별 원응답**을 볼 수 있습니다. 이용자가 "어느 문항에 무엇을 골랐는지
알려 달라"고 요청하실 때 쓰는 자료입니다([9-2](#9-2-개인정보-요청--세-종류와-처리-흐름)).
`선택지 index는 문항 CSV의 options 순서(0부터)입니다` — 즉 `0`이 첫 번째 선택지입니다.

### 11-3. `시나리오 진행` 탭

세 덩어리가 위에서부터 차례로 나옵니다.

**① 영역별 진행** — 영역마다 몇 편을 마쳤는지와 `이어하기 위치`가 표로 나옵니다.
`이어하기 위치`는 **기록이 없는 가장 빠른 회차**입니다(앱이 이어하기 지점을 따로
저장하지 않고 빈자리로 정하기 때문이며, 화면에도 그렇게 적혀 있습니다).

**② 완료 보고서 열람 기록 (seenReports)** — 그 영역의 완료 보고서를 봤는지.

**③ 에필로그 열람 기록 (epilogues)** — **2026-08-26에 추가되었습니다.**
어느 영역의 에필로그를 언제 봤는지가 `직장 (2026-08-26 14:30), 일상 (2026-08-26 15:02)`
처럼 한 줄로 나옵니다.

- `열람한 에필로그가 없습니다.` → 아직 하나도 안 봤다는 뜻입니다.
- `필드가 없습니다 (에필로그를 한 번도 열지 않았거나 그 전에 만들어진 문서).`
  → 오류가 아닙니다. 에필로그 기능이 생기기 전부터 있던 계정이거나, 한 번도 연 적이
  없는 계정입니다.

🔑 **에필로그 열람은 '진행도'가 아닙니다.** 그래서 위 ①의 진행 표에 섞이지 않고 따로
나옵니다. 에필로그는 읽고 끝나는 장면이라 완주 판정에 넣으면 완주율 통계가 왜곡되기
때문입니다. **에필로그를 봤다고 완주 수가 늘지 않고, 안 봤다고 줄지도 않습니다.**

**④ 에피소드별 기록** — 어느 에피소드에서 어떤 전략을 골랐고 도움이 됐다고 했는지가
한 줄씩 나옵니다.

### 11-4. `진행도 정정` 탭 (되돌릴 수 없습니다)

지울 수 있는 것은 세 가지입니다. 각각 펼침 상자로 나뉘어 있습니다.

| 상자 | 무엇을 지우나 |
|---|---|
| `① 에피소드 1건 삭제` | 고른 에피소드 하나의 기록 |
| `② 영역 전체 리셋` | 그 영역의 진행 기록 전부 |
| `③ 검사 결과 삭제` | ADHD 또는 스트레스 검사 결과 (지우면 그 사람은 검사를 처음부터 다시 볼 수 있게 됩니다) |

**어느 것이든 순서는 똑같이 세 단계입니다. 한 번 눌러 끝나지 않게 일부러 그렇게
만들어 두었습니다.**

1. 대상을 고르면 **무엇이 지워지는지 먼저 표로 보여 줍니다.** 그 표를 읽으십시오.
2. 빨간 글씨 아래 `위 내용을 확인했으며, 삭제에 동의합니다.` 체크박스를 켭니다.
   **켜기 전에는 `삭제하기` 버튼이 회색으로 잠겨 있습니다.**
3. `삭제하기`를 누릅니다.

`② 영역 전체 리셋`에는 `완료 보고서 열람 기록(seenReports)에서도 이 영역을 뺍니다`라는
체크박스가 있고 **기본으로 켜져 있습니다. 그대로 두시길 권합니다** — 끄면 진행도만
지워지고 열람 기록이 남아, 그 사람이 영역을 다시 완주해도 완료 보고서가 "이미 봤다"로
처리돼 뜨지 않습니다.

⚠️ **보호 계정 `test@example.com`은 여기서도 잠깁니다**([8-3](#8-3-보호-계정--testexamplecom)).
진행도를 지우면 개발자 전용 화면의 4개 영역 완주 데이터가 사라지기 때문입니다.

> Mock 모드에서는 실제 유저 대신 **연습용 예시 문서**가 뜨고, 삭제해도
> `[시뮬레이션] 이 세션에서만 반영했습니다. 실제 DB는 그대로입니다.`가 나옵니다.
> 절차를 연습해 보기에 좋습니다.

## 14. 막혔을 때 — 증상별 대처

### "CSV를 고쳤는데 앱이 그대로입니다"

가장 흔한 문제입니다. 위에서부터 순서대로 확인하십시오.

1. **앱을 새로고침했습니까?** 맥 `command + R`, 휴대폰은 브라우저 새로고침.
2. **어드민에 업로드했습니까?** 파일만 고치는 것으로는 아무 일도 일어나지 않습니다.
   `시나리오 관리 (CSV)`에서 초록색 `DB 반영됨 …` 표시와 **갱신 시각**을 확인하십시오.
   시각이 방금이 아니면 업로드가 안 된 것입니다.
3. **Mock 모드에서 올리지 않았습니까?** [2-1](#2-1-mock-모드인지-실모드인지-구분하는-법-가장-중요)로
   확인하십시오. 이 경우가 가장 많습니다.
4. **다른 종류를 올리지 않았습니까?** `관리할 CSV 종류`에서 `대사`를 골라 두고 비주얼
   파일을 올린 경우입니다. `현재 DB 내용 미리보기`로 내용을 확인하십시오.
5. 위가 다 맞는데도 안 바뀌면 개발자에게 문의하십시오.

### "업로드 버튼이 안 보입니다"

빨간 오류 상자가 하나라도 있으면 저장 버튼이 나타나지 않습니다. 화면을 위로 올려 빨간
상자를 찾아 읽고, 시트에서 고친 뒤 다시 내려받아 올리십시오.
([4-2](#4-2--어드민에-업로드하기--시나리오)의 오류 표 참조)

### "숫자가 다 0입니다 / 유저가 한 명도 없다고 나옵니다"

Mock 모드일 가능성이 큽니다. [2-1](#2-1-mock-모드인지-실모드인지-구분하는-법-가장-중요)로
확인하십시오. 사이드바 배지가 초록색(`🟢 실모드`)인데도 0이라면 정말로 가입자가 없는
것일 수 있습니다.

### "화면이 안 뜨고 한참 기다리게 됩니다"

인터넷 주소로 접속하셨다면 잠자던 서버가 깨어나는 중입니다. 20~30초 기다리십시오.
[2-4](#2-4-a-인터넷-주소로-접속하기) 참조.

### "방금 바꿨는데 표에 반영이 안 됩니다"

유저 목록은 60초 동안 이전 내용을 보여 줍니다. 1분 기다렸다가 브라우저를 새로고침하십시오.

### "터미널에 빨간 글씨가 잔뜩 나옵니다"

- `command not found` → 명령을 잘못 쳤거나 `venv/bin/`을 빠뜨렸습니다.
- `No such file or directory` → 폴더 위치가 다릅니다. `cd ~/DEV_Mac/syu-react/syu-react-admin`
  부터 다시 실행하십시오.
- `secrets.toml이 없습니다` → Firebase 열쇠 파일이 없습니다. 개발자에게 문의하십시오.
- 그 밖의 오류는 **화면 전체를 복사해** 개발자에게 전달하십시오. 오류 메시지가 원인을
  거의 그대로 알려 줍니다.

### 어디에 물어야 할지 모르겠을 때

1. 이 문서의 목차에서 관련 장을 찾아 봅니다.
2. 어드민 화면 자체에 설명이 붙어 있습니다. 회색 작은 글씨와 파란 안내 상자를 읽으십시오.
3. 그래도 모르겠으면 **무엇을 하려 했는지 · 무엇을 눌렀는지 · 화면에 무엇이 떴는지**
   세 가지를 적어 개발자 또는 팀에 문의하십시오. 이 세 가지가 있으면 대부분 바로 풀립니다.

## 부록 C. 개발자용 스크립트 (저장소와 DB가 어긋났을 때)

> **팀이 쓰실 일은 없습니다.** 여기 있는 것은 터미널에서 개발자가 도는 도구이며,
> 평소 작업은 전부 어드민 화면으로 됩니다. **"저장소와 DB가 어긋났다"는 말이 나왔을 때
> 개발자가 무엇을 하는지** 알아 두시라고 적어 둡니다.

[1장](#1-먼저-알아야-할-용어-다섯-개)에서 본 것처럼 콘텐츠는 **저장소의 CSV 파일**과
**DB(Firestore)** 두 곳에 삽니다. 앱은 DB를 보고, 저장소는 백업 겸 예비용입니다. 어드민
업로드만 하고 저장소를 안 고치면 저장소 쪽이 조용히 옛날 내용으로 남습니다
([4-5](#4-5--저장소github에도-반영--빠뜨리기-쉬움)).

두 스크립트 모두 `syu-react-admin` 폴더에서 돌리며, `.streamlit/secrets.toml`(Firebase
열쇠)이 있어야 동작합니다.

### ① `check_csv_sync.py` — 어긋났는지 본다 (읽기 전용, 안전)

```bash
cd ~/DEV_Mac/syu-react/syu-react-admin
venv/bin/python check_csv_sync.py
```

`questions` 2개(adhd·stress)와 `scenarios` 4개(visual·dialogue·angels·epilogue), 총 여섯
문서를 저장소 파일과 하나씩 대조해 `✅ 일치` / `⚠️ 불일치` / `DB 문서 없음`을 출력합니다.
**아무것도 바꾸지 않습니다.** 출력 예시와 읽는 법은 [4-5](#4-5--저장소github에도-반영--빠뜨리기-쉬움)에
있습니다.

### ② `push_csv_to_firestore.py` — 저장소 CSV를 DB로 민다

어드민 업로드와 **방향이 반대**입니다. 저장소 파일이 최신일 때(개발자가 코드와 함께
CSV를 고쳤을 때) 그것을 DB에 반영하는 도구입니다.

```bash
cd ~/DEV_Mac/syu-react/syu-react-admin
venv/bin/python push_csv_to_firestore.py scenarios/epilogue            # 확인만 (아무것도 안 씀)
venv/bin/python push_csv_to_firestore.py scenarios/epilogue --apply    # 실제로 씀
```

- **`--apply`를 붙이지 않으면 아무것도 쓰지 않습니다.** 백업을 뜨고, 지금 DB와 저장소
  파일이 몇 줄 다른지만 알려 주고 끝납니다. 그래서 앞줄은 안심하고 돌려 보셔도 됩니다.
- 쓰기 전에 **DB의 현재 내용을 파일로 먼저 백업**합니다
  (`~/DEV_Mac/syu-react-asset-drafts/<날짜>-firestore-backup/`).
- 어드민 업로드와 **같은 방식으로** 저장하므로, 잘못 밀었어도 어드민의
  `이전 버전으로 되돌리기`로 되돌릴 수 있습니다([4-6](#4-6-잘못-올렸을-때--되돌리기-1단계)).
- 뒤에 붙이는 이름은 `scenarios/visual`·`scenarios/dialogue`·`scenarios/angels`·
  `scenarios/epilogue`·`questions/adhd`·`questions/stress` 여섯 가지입니다.
